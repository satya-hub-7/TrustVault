# TRUSTVAULT — COMPLETE FULL-STACK APPLICATION BUILD

Act as a senior full-stack engineer, security engineer, product designer, and UI/UX specialist. Build a complete, functional, premium-quality web application called **TrustVault — Secure Document Sharing with a Verifiable Audit Trail**.

This is a serious hackathon project. I do not want a generic AI-generated website, a basic dashboard template, a frontend-only mockup, or a collection of non-functional buttons. I want a distinctive, polished, secure, fully integrated application with complete source code that I can run, understand, modify, and submit through GitHub.

## 1. Project objective

TrustVault solves a critical business problem: companies need to share confidential documents without allowing unauthorized people to read them, and they need reliable evidence of who accessed a document and when.

The core principle is:

**"Your documents. Your rules. Your proof."**

The application must provide:
- Secure authentication and authorization.
- Private document upload, storage, and management.
- Explicit document-level sharing permissions.
- Immediate server-enforced access revocation.
- A verifiable audit trail for document access and security-sensitive actions.
- Clear separation between administrators, document owners, and viewers.

Do not claim that a feature is secure unless the implementation actually enforces it on the server.

## 7. User roles and access control

Implement at least these three roles:

**Administrator**
- Can manage users and review system-level audit information according to defined policies.
- Can administer the application.
- Must not automatically receive unrestricted access to every confidential document unless the application explicitly defines and enforces that policy.

**Document Owner**
- Can upload and manage owned documents.
- Can grant and revoke access to owned documents.
- Can review relevant access activity for owned documents.

**Viewer**
- Can view or download only documents explicitly shared with them, according to their assigned permissions.
- Cannot manage another user's documents or grant themselves additional permissions.

Enforce authorization on every relevant backend endpoint. Verify the authenticated user's identity, role, document ownership, and current permission before serving protected resources.

Prevent horizontal and vertical privilege escalation, insecure direct object references, and unauthorized cross-user document access.

## 9. File storage and document security

Implement private document storage.

- Store file metadata in PostgreSQL.
- Keep uploaded files outside the public web root or in private object storage.
- Never expose unrestricted direct public file URLs.
- Validate file type, file size, and uploaded content appropriately.
- Generate safe server-controlled storage names.
- Prevent path traversal and malicious upload handling.
- Authenticate and authorize every document download.
- Check current permissions at the time of access.
- Revoke access immediately after a successful permission-revocation operation.
- Do not expose sensitive file paths, database credentials, JWT secrets, or internal errors to users.

Where feasible, use encryption at rest and secure transport in deployment. Clearly document what is actually implemented and what depends on deployment configuration.

Do not describe a normal file upload as end-to-end encrypted unless true end-to-end encryption has actually been implemented.
